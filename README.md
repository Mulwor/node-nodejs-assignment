# File Manager - файловый менеджер

## Необходимо реализовать файловый менеджер используя API Node.js. 

Он должен уметь:

- Работать через командную строку (CLI)
- Выполнять основные файловые операции (копирование, перемещение, удаление, переименование и т.д.)
- Использовать Streams API
- Получать информацию об операционной системе хостовой машины
- Выполнять расчёты хешей
- Сжимать и распаковывать файлы

## Технические требования:

- Нельзя использовать посторонние библиотеки, только встроенные (native) модули Node.js
- Необходимо использовать 24 версию Node.js
- Программа запускается через npm-команду - `npm run start -- --username=your_username`. После запуска программа отобразит в консоли следующий текст (`Username` равно значению, которое было передано при запуске приложения в аргументе CLI `--username`) => `Welcome to the File Manager, Username!`
- После завершения работы программы (нажатия "ctrl + c" или отправки пользователем команды ".exit" в консоль) программа отобразит в консоли следующий текст => `Thank you for using File Manager, Username, goodbye!`
- При запуске программы и после каждого завершения ввода/операции текущая рабочая директория должна выводиться следующим образом: `You are currently in path_to_working_directory`
- Начальный рабочий каталог - это домашний каталог текущего системного пользователя (например, в Windows это что-то вроде `system_drive/Users/Username`)
- По умолчанию программа должна предлагать пользователю в консоли печатать команды и ждать результатов
- В случае неизвестной операции или неверного ввода (отсутствие обязательных аргументов, неверные данные в аргументах и т.д.) Должно отображаться сообщение `Invalid input`, и пользователь должен иметь возможность ввести другую команду
- В случае ошибки во время выполнения операции должно отображаться сообщение `Operation failed`, и пользователь должен иметь возможность ввести другую команду (например, попытка выполнить операцию с несуществующим файлом - `attempt to perform an operation on a non-existent file` или работа с несуществующим путем должна привести к сбою операции - `work on a non-existent path should result in the operation fail`).
- Пользователь не может зайти выше корневого каталога (например, в Windows это корневой каталог текущего локального диска). Если пользователь попытается это сделать, текущий рабочий каталог не изменится

## Список операций и их синтаксис:

- навигация & рабочая директория (working directory - nwd): 
  - `up` - Идет наверх из текущего каталога (когда вы находитесь в корневой папке, эта операция не должна изменять рабочий каталог). Аналог: cd ..
  - `cd path_to_directory` - Он может быть как абсолютным, так и относительным. Переходит в определенную папку
  - `ls` - выводит в консоль список всех файлов и папок в текущем каталоге. Список должен содержать: 
    - имена файлов и папок (для файлов - с расширением)
    - папки и файлы сортируются в алфавитном порядке по возрастанию, но список папок идет первым
    - тип содержимого каталога должен быть указан явно (например, в виде соответствующего значения столбца).
- простые операции с файлами: 
  - `cat path_to_file` - читает файл и показывает содержимое в консоли (необходимо сделать с помощью readable stream);
  - `add new_file_name` - создает пустой файл в текущем рабочей директории
  - `mkdir new_directory_name` - создает новую папку в текущем рабочей директории
  - `rn path_to_file new_filename` - переименовывает только название файла, содержимое остается неизменным
  - `cp path_to_file path_to_new_directory` - копирует файл (необходимо сделать с помощью writable and readable streams);
  - `mv path_to_file path_to_new_directory` - перемещает файл (аналогично копированию, но исходный файл удален, часть копирования должна выполняться с использованием потоков, доступных для чтения и записи):
  - `rm path_to_file` - удаляет файл
- Информация об операционной системе (выводит следующую информацию в консоль):
  - `os --EOL` - получает EOL (системный конец строки по умолчанию) и показывает его на консоли
  - `os --cpus` - получает информацию о процессорах хост-компьютера (общее количество процессоров плюс модель и тактовая частота (в ГГц) для каждого из них) и распечатайте ее на консоли
  - `os --homedir` - получает домашний каталог и распечатайте его на консоли
  - `os --username` - получает текущее системное имя пользователя (не путайте с именем пользователя, которое задается при запуске приложения) и выведите его на консоль
  - `os --architecture` - получает архитектуру процессора, для которой Node.js был скомпилирован двоичный файл, и выведите его на консоль
- Вычисление хеша (hash):
  - `hash path_to_file` - вычисляет хэш для файла и выводит его в консоль
- Операция сжатия (compress) и распаковки(decompress) файла:
  - `compress path_to_file path_to_destination` - сжатие файла (с использованием алгоритма Brotli, должно выполняться с использованием Streams API)
  - `decompress path_to_file path_to_destination` - распаковать файл (используя алгоритм Brotli, следует выполнять с помощью Streams API). ПРИМЕЧАНИЕ! После распаковки ранее сжатого файла результат не должен отличаться от исходного сжатого файла
